# V2 Roadmap: Clinical EKG Classifier

With the successful deployment of the V1 architecture (Squeeze-and-Excitation ResNet + Self-Attention LSTM, Databricks MLflow integration, and robust Data Augmentation), the core modeling pipeline is complete.

The V2 Roadmap outlines the next evolution of this project, focusing on **Explainable AI (XAI)**, **Edge Deployment**, and **Enterprise MLOps**.

---

## Phase 1: Visual Interpretability (Explainable AI)

To maximize clinical adoption, cardiologists must be able to trust the model's predictions. We will expose the internal logic of the neural network visually.

- [ ] **Extract Attention Weights**: Modify `predict.py` to extract the exact sequence-level weights generated by the Self-Attention layer.
- [ ] **Signal Overlay Heatmaps**: Develop a plotting script (e.g., using `matplotlib` and `seaborn`) that overlays these attention weights onto the raw 12-lead EKG waveform as a color-coded heatmap.
- [ ] **Grad-CAM Integration**: Implement Gradient-weighted Class Activation Mapping (Grad-CAM) on the 1D ResNet to visualize which specific spatial features (e.g., P-waves, QRS complexes, T-waves) triggered the specific SNOMED-CT diagnosis.

## Phase 2: Edge Device Deployment (Low Latency)

While Databricks Model Serving provides a highly scalable REST API, certain medical use cases (like continuous Holter monitors or smartwatches) require offline, ultra-low-latency inference directly on the edge device.

- [ ] **ONNX Export**: Write an `export.py` script to trace the PyTorch model and compile it into the Open Neural Network Exchange (ONNX) format.
- [ ] **Quantization**: Apply dynamic INT8 quantization to the ONNX graph to shrink the model size (bytes) and drastically reduce CPU inference time without sacrificing the Macro F1 score.
- [ ] **TensorRT Optimization**: (Optional) For high-throughput hospital hardware, compile the ONNX model into an NVIDIA TensorRT engine to maximize GPU utilization.

## Phase 3: Enterprise MLOps (Databricks Unity Catalog)

Transition the project from basic MLflow tracking into a full, automated CI/CD lifecycle using the Databricks Unity Catalog.

- [ ] **Model Registry Promotion**: Automate the promotion of the `EKG_CRNN_Classifier` model from the MLflow Experiment tracking into the official Unity Catalog.
- [ ] **Automated CI/CD Validation**: Write an automation script that evaluates the newly trained model against a holdout test set. If the `Macro ROC-AUC` exceeds a predetermined baseline (e.g., `0.85`), automatically tag the model with the `Staging` or `Production` alias.
- [ ] **Data Drift Monitoring**: Implement Databricks Lakehouse Monitoring to detect if incoming hospital EKG data statistically deviates from the PhysioNet training distribution over time.
